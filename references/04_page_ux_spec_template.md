# 阶段3 · 页面级 UI/UX 设计稿模板

对 PRD 里 sitemap 列出的每个页面，按下面的结构逐一产出设计说明。如环境支持可视化工具（如生成实际线框图/高保真稿），优先用可视化呈现给用户确认；不支持的话用结构化文字描述清楚布局、内容、交互。

## 通用模板（每个页面/模块都要回答这几个问题）

```markdown
### 页面/模块名称

**用户在这里想做什么？**（一句话）

**视觉焦点是什么？**（用户进入这个区域，眼睛第一个会落在哪，为什么）

**布局结构**
（按从上到下/从左到右描述区块排列，注明响应式断点下的变化）

**核心交互**
（点击/滚动/输入会发生什么，状态变化如何呈现）

**需要的视觉素材**
（图片/插画/图标，标注是否已有素材可用或需要生图，交给阶段4处理）

**下一步引导**
（完成这个区域的目标行为后，用户视线/动作自然被引向哪里）
```

## 首页 Hero 区 —— 重点设计，需要额外回答

- **核心一句话主张**：用户 3 秒内要理解"职映是干什么的"
- **次要说明文案**：补充说明差异化卖点（来自 PRD 第3点）
- **主视觉构图**：是用 IP 形象做主角、还是产品截图/示意图为主、还是抽象图形+渐变背景；构图要服务于"快速建立信任感+引导点击 CTA"这个目标，不要为了好看堆砌无关元素
- **首屏 CTA**：唯一的主要行动按钮文案和位置（如"开始构建我的知识库"），避免首屏出现多个平级 CTA 分散注意力
- **信任信号**：是否需要在首屏或紧接其后展示用户证言/数据/案例，强化可信度

## 核心功能页面专项要点

- **知识库构建页**：体现 resumecraft 的"分模块、一步步引导、不接受空话"的特点，设计上应该是渐进式的（进度条/步骤指示），每完成一个模块给正向反馈，避免用户觉得"要填的东西好多，好麻烦"
- **岗位匹配分析页**：三分组结果（直接匹配/可强调关联/待补强项）要用视觉上能一眼区分的方式呈现（如颜色编码+图标），不要做成纯文字列表
- **简历生成与预览页**：左侧/上方编辑，右侧/下方实时预览（或类似的高效布局），下载/导出按钮要醒目，多版本管理入口清晰可见

## 完成标准

每个页面设计稿产出后，向用户简述设计意图（为什么这样设计、解决了什么体验问题），收集反馈后再定稿，定稿的设计稿集合作为阶段7 开发执行的直接依据。
