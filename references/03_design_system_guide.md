# 阶段2 · 设计系统构建方法论

设计系统是后面所有页面设计和开发共用的"地基"，必须先做，且必须从用户已有的 Logo/IP 形象里提炼，而不是凭空发明一套新审美。

## 1. 色彩体系：从已有资产提炼

1. 实际打开 Logo 和 IP 形象文件，用图像工具或目测取色，提取其中出现的 2-4 个关键色值
2. 判断哪个是「主色」（最能代表品牌、出现在关键 CTA 和强调位置）、哪个适合做「辅助色」（用于次要强调、图表、标签）
3. 围绕主色和辅助色，补齐一套完整的语义化色板：
   - 主色（Primary）：50-900 共 9-10 级色阶，用于按钮、链接、关键强调
   - 辅助色（Secondary/Accent）：用于次要强调、装饰
   - 中性色（Neutral/Gray）：9-10 级，用于文字、背景、边框
   - 语义色：成功(绿)/警告(黄)/错误(红)/信息(蓝)，除非品牌色本身已经是这几色之一，否则用业界通用色，不要为了统一硬凑成主色调（错误提示用品牌粉色会让用户分不清这是不是出错了）
4. 验证可访问性：正文文字与背景的对比度至少达到 WCAG AA 标准（4.5:1），不要因为好看牺牲可读性

## 2. 字体系统

- 中文字体：优先选择网页端渲染清晰、有完整字重(weight)选择的字体（如思源黑体/苹方/系统默认字体栈），避免使用只有单一字重的"美术字体"做正文
- 英文/数字字体：可以和中文字体气质不同但要协调，比如中文用偏圆润的字体配数字用偏几何感的英文字体，提升精致感
- 字号阶梯：建立一套有限的字号系统（如 12/14/16/18/24/32/48/64px），所有页面统一使用这套阶梯，不要随手写新字号
- 行高与字重：正文行高建议 1.5-1.7 倍，标题字重通常 600-700，正文 400-500

## 3. 间距与网格

- 用统一的间距单位（如 4px 或 8px 的倍数）建立间距阶梯，避免页面里出现 13px、17px 这种随手定的数值
- 定义桌面端最大内容宽度（如 1200-1440px）和栅格列数，移动端单独定义边距和断点

## 4. 组件视觉规范

- 圆角：定义 1-3 档圆角值（如小组件 6px、卡片 12px、大容器 16-24px），统一全站调性（圆角越大越显年轻活泼，越小越显严谨专业，要呼应 IP 形象的性格）
- 阴影：定义 2-3 档阴影强度，用于区分层级（卡片悬浮、弹窗、下拉菜单），避免乱用阴影显得杂乱
- 边框/分割线：定义统一的颜色和粗细

## 5. 动效原则

- 缓动曲线：交互反馈用快速自然的曲线（如 ease-out，150-250ms），页面级转场可以稍长（300-500ms），避免所有动效用同一个生硬的线性曲线
- 使用场景：按钮反馈、卡片悬浮、页面切换、加载态、表单校验反馈、关键操作完成后的庆祝反馈（如知识库自检通过、简历生成完成）——这些地方值得花心思设计动效，是体验记忆点
- 克制原则：装饰性动效不能拖慢操作路径，加载动效不能让用户等得心烦（控制在用户能感知"系统在动"但不超过其耐心阈值）

## 6. 组件库与技术选型建议

根据阶段5 确定的技术栈推荐匹配的组件库方向，原则上选择：生态成熟、可深度定制（不是只能用默认皮肤）、和动效库兼容性好的方案。例如 React 生态可考虑 Tailwind CSS + shadcn/ui（基于 Radix，方便深度定制，不像许多 UI 库长得"一看就是用了某个库没改过"）配合 Framer Motion 做动效；如技术栈不同则按同样标准（成熟、可定制、生态活跃）寻找对应方案。

最终交付物：一份完整的设计系统说明文档（色值表、字体规范、间距阶梯、组件规范、动效规范、组件库选型说明），如环境支持，配一张可视化的设计系统总览图/页面。
