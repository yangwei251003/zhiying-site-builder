# 阶段0 · 头脑风暴与交流方式指南

## 目的

在动手设计/开发之前，确保 agent 和用户对"要做什么、为谁做、做成什么样"有完全一致的理解。这一步省略掉，后面返工的代价会远大于多聊几轮的时间成本。

## 头脑风暴的提问顺序（建议，可根据对话自然调整）

1. **从故事切入**：先让用户描述"一个典型用户打开职映网站，会经历什么"，而不是直接问功能列表——故事里自然会带出真实的功能需求和优先级。
2. **追问动机**：每当用户提出一个功能，多问一句"这个功能解决的是用户的什么具体困扰"，避免堆砌"看起来不错但用户其实不需要"的功能。
3. **聚焦差异化**：直接问"如果用户去用其他同类工具，职映非要存在的理由是什么"，逼出真正的核心卖点，这个卖点应该成为首页 Hero 区文案和视觉的中心。
4. **明确边界**：问清楚"第一版上线必须有"和"可以后面再加"的边界，避免 MVP 范围无限膨胀导致迟迟上不了线。
5. **资产盘点时同步问审美偏好**：看用户提供的 IP 形象/Logo 时，顺便问"你希望网站整体给人的感觉是怎样的三个形容词"，这对后面设计系统定调很有用。

## 交流方式要求

- 每轮对话控制在少量问题内（1-3个），不要一次甩一长串问题清单
- 用户给出模糊回答时（"差不多就行""你看着办"），不要直接接受，至少给出2-3个具体方向让用户选,降低用户的决策负担,同时还原获得明确信号
- 收集到关键信息后，主动做一次小结复述："目前理解是……，这样对吗？" 等用户确认才继续
- 如果用户中途提供了和之前说法矛盾的信息，礼貌指出矛盾并请用户确认以哪个为准，不要自己悄悄选一个

## 阶段0 结束的判定标准

满足以下条件才能进入阶段1（PRD）：

- [ ] 能用一段话讲清楚网站定位、目标用户、核心差异化卖点
- [ ] 已经看过并分析了用户提供的全部视觉资产
- [ ] 已明确 MVP 功能范围和后续迭代范围
- [ ] 用户已经对上述理解明确表示确认
