# 阶段1 · 产品需求文档（PRD）模板

把阶段0 收集的信息整理成下面这份结构化文档，输出给用户确认。**确认通过才能进入设计系统阶段。**

```markdown
# 职映（ZhiYing）产品需求文档

## 1. 产品定位
一句话定位 / 目标用户 / 核心差异化卖点 / 商业模式

## 2. 用户画像
- 主要用户群体特征（求职阶段、行业、痛点）
- 典型用户旅程（从第一次打开网站到拿到一份满意简历的完整路径）

## 3. 网站地图（Sitemap）
列出所有页面及层级关系，例如：
- 首页（Hero + 功能介绍 + 信任背书 + CTA）
- 知识库构建页（多步骤引导表单/对话式收集）
- 岗位匹配分析页
- 简历生成与预览页（含编辑、多版本管理）
- 个人中心（账号、历史记录、订阅状态）
- 价格页（如涉及付费）
- 关于/帮助/隐私政策/用户协议

## 4. 功能清单与优先级

| 功能 | 描述 | 优先级(P0/P1/P2) | 对应 resumecraft 阶段 |
|---|---|---|---|
| 知识库引导收集 | ... | P0 | collecting |
| 完整性自检反馈 | ... | P0 | self_check |
| 岗位JD解析与匹配分析 | ... | P0 | job_matching |
| 简历生成与下载 | ... | P0 | generating |
| 学习路径建议 | ... | P1 | — |
| 多简历版本管理 | ... | P1 | — |
| 账号体系/订阅付费 | ... | P1/P2（视商业模式而定） | — |

P0 = MVP 必须有，P1 = 第二阶段，P2 = 长期规划，先记录不开发。

## 5. 非功能性需求
- 性能（首屏加载时间目标）
- 响应式适配范围（手机/平板/桌面）
- 多语言需求
- 隐私与数据安全要求（用户简历内容属于敏感个人信息，需明确存储和访问策略）

## 6. 成功指标
定义"这个网站做得好不好"的衡量方式（如完成知识库构建的转化率、生成简历的留存使用率等），哪怕第一版无法全部追踪，先明确目标。
```

填写时所有占位内容必须替换为基于阶段0 真实收集到的信息，不要留模板原文。完成后整篇呈现给用户，明确问一句"这份 PRD 是否符合你的预期，有没有需要调整的地方"，得到确认后才进入阶段2。
