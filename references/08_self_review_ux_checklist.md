# 阶段8 · 用户视角自检清单

第一版网站做完后，**真实地代入一个第一次访问的新用户**，从零走一遍完整流程，而不是凭印象判断"应该没问题"。建议实际操作一遍（点击、输入、查看每个状态），记录下面这些维度的问题。

## 走查路径
首页 → 注册/进入 → 知识库构建（完整走完所有模块）→ 完整性自检 → 提交一份真实JD → 查看匹配分析 → 生成简历 → 下载查看

## 检查维度

**第一印象（首页 5 秒测试）**
- 5秒内能看懂这个网站是做什么的吗？
- 第一眼会被引导去点哪里？是不是就是希望用户点的那个 CTA？

**认知负荷**
- 有没有哪个环节用户需要停下来想"接下来该干什么"？
- 表单/步骤是否过长导致中途想放弃？

**反馈及时性**
- 每个操作之后，用户能立刻感知到"系统收到了我的操作"吗（加载态、成功提示）？
- 出错时提示是否清楚说明了原因和怎么解决，而不是一个生硬的报错？

**视觉一致性**
- 各页面的色彩、字体、间距、组件样式是否统一，有没有"一看就是不同时间写的代码"的违和感？
- 生成的素材和已有 IP/Logo 放在一起协调吗？

**移动端体验**
- 手机上操作是否顺畅，按钮是否好点击，文字是否需要缩放才能看清？

**性能体感**
- 页面切换、生成简历等待的过程是否让人觉得"卡住了"？

## 处理方式

把发现的问题列成清单，每条标注严重程度（影响核心流程完成 / 影响体验但不阻断 / 细节瑕疵），优先修复影响核心流程的问题，修完后重新走查一次该路径，直到顺畅为止。这个走查记录本身也作为交付物的一部分，证明体验是被认真验证过的，不是凑出来的。
