# 阶段9 · 交付文档清单

四类文档，目标是"换一个没参与开发的人也能看懂怎么用、怎么维护"。

## 1. 开发文档
- 项目结构说明（目录组织、各模块职责）
- 技术栈与版本依赖
- 本地开发环境搭建步骤（从拉代码到跑起来的完整命令）
- 设计系统使用说明（如何引用色彩/字体 token，如何用已封装的组件）
- 编码规范（如有）

## 2. 接口文档
- 沿用阶段5 产出的 API 文档，确保和实际实现一致（开发过程中接口若有调整，文档要同步更新，不能上线时文档是过时版本）

## 3. 测试文档
- 测试范围（哪些核心流程有自动化测试覆盖，哪些靠人工走查）
- 关键测试用例清单（覆盖阶段8 走查发现的问题点，确保回归不再出现）
- 已知问题/限制说明（如果有些边缘情况暂未处理，明确写出来，不要藏着）

## 4. 运维文档
- 部署流程（从代码到生产环境上线的完整步骤）
- 环境变量/密钥管理说明
- 监控与告警（如果配置了，说明监控了什么指标、告警阈值）
- 常见故障排查指引（如"生成简历失败"常见原因排查顺序）
- 数据备份策略（用户知识库和简历数据的备份频率与恢复方式）

## 5. 用户文档/帮助中心内容
- 新用户引导说明（如何开始构建知识库）
- 常见问题 FAQ（如"为什么有些技能没写进我的简历里" —— 借此机会向用户解释清楚平台"不编造内容"的设计理念，这也是建立信任的机会）
- 联系/反馈渠道说明

所有文档完成后，做一次整体交付清单核对：开发文档、接口文档、测试文档、运维文档、用户文档是否齐全且与实际上线版本一致。
